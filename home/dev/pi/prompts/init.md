为当前仓库创建或更新项目根目录的 `AGENTS.md` 指令文件, 帮助未来的 pi / opencode
等 agent 会话快速理解项目并避免犯错。

用户提供的焦点或约束 (如有, 须优先考虑): $@

## 目标

生成一份紧凑的指令文件。每一行都应能回答: "没有这一行, agent 是否很可能出错?"
若答案是 "不会", 就删掉它。

## 调查步骤

1. 先确定仓库根目录: 用 `git rev-parse --show-toplevel` 查找; 若不在 git 仓库中,
   以当前工作目录为根。
2. 按价值从高到低读取文件:
   - `README*`、根级清单文件 (package.json / Cargo.toml / pyproject.toml /
     flake.nix 等)、工作区配置、锁文件
   - 构建、测试、lint、格式化、类型检查、代码生成配置
   - CI 工作流与 pre-commit / 任务运行器配置
   - 已有指令文件: `AGENTS.md`、`CLAUDE.md`、`.cursor/rules/`、`.cursorrules`、
     `.github/copilot-instructions.md`、`opencode.json`、`.pi/` 等,
     提取其中仍有效的部分
3. 读完后架构仍不清楚时, 再挑少量有代表性的代码文件, 找真实入口点、
   包边界与执行流; 优先读能解释系统如何组装的文件, 不要随机挑叶子文件。
4. 事实来源优先于文字: 文档与配置/脚本冲突时, 以可执行内容为准,
   只保留能验证的信息。

## 提取什么

提取对 agent 最有价值的仓库特定事实:

- 精确的开发命令, 尤其是非显而易见的
- 运行单个测试、单个包或一次聚焦验证的方法
- 有要求的命令顺序, 如 `lint -> typecheck -> test`
- monorepo / 多包边界、主要目录归属、真实的应用/库入口点
- 框架或工具链怪癖: 生成代码、迁移、codegen、构建产物、特殊环境变量加载、
  开发服务器、部署流程
- 与语言或框架默认习惯不同的仓库约定
- 测试怪癖: fixtures、集成测试前置条件、快照工作流、依赖的外部服务、
  易挂或昂贵的套件
- 已有指令文件中值得保留的重要约束

## 提问 (仅当必要)

仅当仓库本身无法回答某个关键问题时才提问, 且最多一次、限制在几个问题内
(直接以文字列出, 等待用户回答后继续)。好的问题:

- 未写入文档的团队约定
- 分支 / PR / 发布期望
- 已知但未记录的环境或测试前置条件

不要问仓库已能回答的问题。没有关键疑问就直接生成, 不要为提问而提问。

## 写作规则

只写高信号、仓库特定的内容, 例如:

- 精确命令与快捷方式 (agent 猜错代价高的)
- 从文件名看不出来的架构说明
- 与默认不同的约定
- 环境要求、怪癖与运维陷阱
- 值得引用的既有指令来源

排除:

- 泛泛的软件工程建议
- 长篇教程或详尽的文件树
- 显而易见的语言约定
- 无法验证的推测

拿不准就删。优先短章节 + 要点; 仓库简单就保持文件简单; 仓库庞大就总结
少数几个真正影响 agent 工作方式的结构性事实。

若 `AGENTS.md` 已存在: 就地改进而非盲目重写, 保留已验证有用的指导,
删除废话或过时声明, 并与当前代码库核对一致。

## 语言

内容语言与仓库现有文档/注释一致; 仓库无明显语言倾向时使用简体中文。

## 输出要求

用 write 工具将最终内容写入仓库根目录的 `AGENTS.md` (若已存在则用 edit
就地改进)。完成后简短汇报: 新建还是更新、包含哪些要点、 以及哪些信息
(如团队约定、部署细节) 建议用户手动补充。
